# Support

This page helps you find the right place for Astra questions and problems.
GitHub Issues are the public, community support channel; response times are not
guaranteed and no service-level agreement applies.

## Before opening an issue

Check the [getting started guide](docs/quickstart/README.md),
[configuration reference](docs/reference/configuration.md), and
[troubleshooting guide](docs/guides/troubleshooting.md). Search existing open
and closed issues as well.

When you open an issue, choose the form that best matches your request:

- [Question](https://github.com/matrixorigin/Astra/issues/new?template=question.yml)
  for usage and configuration help.
- [Bug report](https://github.com/matrixorigin/Astra/issues/new?template=bug_report.yml)
  for reproducible incorrect behavior.
- [Documentation](https://github.com/matrixorigin/Astra/issues/new?template=documentation.yml)
  for missing or inaccurate documentation.
- [Feature request](https://github.com/matrixorigin/Astra/issues/new?template=feature_request.yml)
  for new capabilities and product ideas.

## What to include

For technical problems, include enough information to reproduce and diagnose
the behavior:

- Astra version or Git commit.
- Deployment profile: CLI + Server, Server, or Server + Edge.
- Operating system and CPU architecture.
- Minimal reproduction steps, expected behavior, and actual behavior.
- Relevant sanitized logs, errors, or traces.

Never post API keys, tokens, passwords, private URLs, private filesystem paths,
customer data, or other proprietary information. Redact sensitive values from
logs, traces, screenshots, and configuration before attaching them.

## Reporting a security vulnerability

Do not report security problems through GitHub Issues. Follow
[SECURITY.md](SECURITY.md) to report them privately instead.

## Contributing a fix

If you want to submit a fix or improvement, see [CONTRIBUTING.md](CONTRIBUTING.md)
for the development workflow and pull request expectations.
